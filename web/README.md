# Pain au chocolat de Paris — web

A fast, static Next.js + MapLibre GL frontend for the same data as the
Streamlit app at the repo root. Deployed on Vercel; the Streamlit app
stays as the reference implementation and is unaffected by anything here.

## Architecture

- **Data**: static JSON under `public/data/` (`places.json` + one review
  shard per bakery under `public/data/places/`), regenerated by
  `uv run pac export-web-json` from the pipeline's `pac_app.duckdb` and
  committed to git. No database, no API routes, no server function on the
  hot path — Vercel serves `public/` straight off its CDN.
- **Map**: MapLibre GL JS (WebGL), native clustering, a CARTO Positron
  raster basemap. See `components/map/`.
- **State**: every filter, the active tab, the selected bakery, and the
  ranking sort live in the URL via `nuqs` (`lib/filters.ts`) — views are
  bookmarkable and shareable.
- **Styling**: hand-written CSS Modules + a token layer in
  `app/globals.css` (spacing/radius/shadow/type/motion scales, semantic
  surface/text/border colors). No Tailwind, no component library.
- **Data-encoded color** (score scale, confidence, sentiment) lives in
  `lib/theme.ts`, kept in sync by hand with `src/pac/webapp/theme.py` on
  the Python side — MapLibre paint expressions need real JS values, not
  CSS custom properties.

## Getting started

```bash
npm install
npm run dev       # http://localhost:3000
npm run typecheck
npm run lint
npm run build
```

## Refreshing the data

From the repo root, after a new scoring run:

```bash
uv run pac export-app-db
uv run pac export-web-json   # regenerates web/public/data/
```

Then commit the changed files under `web/public/data/` and push — Vercel
rebuilds automatically.

## Deployment

Vercel project settings: **Root Directory = `web`**, framework preset
Next.js (auto-detected), default build/install/output settings. No
`vercel.json` — long-lived cache headers for `/data/*` live in
`next.config.ts`.
